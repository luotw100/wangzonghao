## 一、核心理念转变

### 旧模型（半双工 Request-Response）

```
用户发消息 → 取消旧计划 → 调LLM → 生成1-3条回复 → 逐条发送
用户再发消息 → 取消旧计划 → 调LLM → ...
```

**问题**：
- 用户连发多条消息时，每条都触发一次「取消+重来」，导致 Robot 总是「欲言又止」
- LLM 被调用的时机完全由用户消息驱动，Robot 是被动的
- 回复条数固化，缺乏真人的动态节奏感

### 新模型（全双工 + 草稿模型）

**核心思想**：Robot 是一个「持续存在的人」，脑子里永远有一份「草稿」。

```
时间线：

用户:  ──[嗨]──────[在吗]──[想你了]────────────────────[那个..]──
Robot: ────────────────────────────[嗯？]─[怎么了]──────────────[嗯]─[说]─
```

真人聊天的心智模型：
1. 看到消息 → 脑子里打草稿 → 发出去
2. 发到一半新消息进来 → 当前这条发完 → 看看新消息 → 决定是继续原来的草稿还是改
3. **草稿不会因为新消息而凭空消失**，而是被重新审视

## 二、全双工 Runtime 架构

### 2.1 核心概念：Session Controller

每个活跃 Session 对应一个 **SessionController**（asyncio Task），它是 Robot 在该对话中的「大脑」。

```
                     ┌─────────────────────────┐
  Redis inbox ──────►│   Consumer Loop          │
                     │   (分发消息到对应Session) │
                     └────────┬────────────────┘
                              │
          ┌───────────────────┼───────────────────┐
          ▼                   ▼                   ▼
  ┌──────────────┐   ┌──────────────┐   ┌──────────────┐
  │ Session Ctrl │   │ Session Ctrl │   │ Session Ctrl │
  │   (s_abc)    │   │   (s_def)    │   │   (s_ghi)    │
  │              │   │              │   │              │
  │ inbox_queue  │   │ inbox_queue  │   │ inbox_queue  │
  │ send_queue   │   │ send_queue   │   │ send_queue   │
  │ state_machine│   │ state_machine│   │ state_machine│
  └──────────────┘   └──────────────┘   └──────────────┘
```

### 2.2 锁定模型（Pending Model）

**核心洞察**：真人脑子里永远有一份「草稿」。收到新消息后，真人不会把脑子格式化，而是重新审视草稿——保留、修改、或推倒重来。

**映射到 LLM**：
- LLM 的一次调用结果 = Robot 脑子里的一份计划
- 计划中已发出的部分 = 已说出口的话（不可撤回）
- 计划中未发出的部分 = 还没说出口的话（可以改）
- 新消息进来时，把未发出的消息「锁定」，交给 LLM 决定每条的命运（保留/修改/取消）

### 2.3 SessionController 状态机

```
    ┌───────┐  user_msg   ┌──────────┐  llm_response   ┌──────────┐
    │ IDLE  │────────────►│ THINKING │────────────────►│ SENDING  │
    │       │             │ (调LLM)  │                  │(逐条发送) │
    └───────┘             └──────────┘                  └──────────┘
        ▲                      ▲                            │  │
        │                      │                            │  │
        │  all_sent            │ user_msg                   │  │
        │  (无新消息)          │ (锁定待定消息，重新思考)      │  │
        └──────────────────────┴────────────────────────────┘  │
                               ▲                               │
                               │ sending完成,有新消息           │
                               └───────────────────────────────┘
```

### 2.4 关键行为流程

#### 场景 1：正常对话

```
1. IDLE → 用户发消息
2. 存入 DB → 进入 THINKING → 调 LLM（无待定消息，pending=[]）
3. LLM 返回 {"pending": [], "messages": [...]} → 写入 DB(status=scheduled)
4. 进入 SENDING → 逐条 sleep + 发送 + 标记 sent
5. 全部发完 → 检查：有无新用户消息？
   - 无 → 回到 IDLE
   - 有 → 回到 THINKING
```

#### 场景 2：发送中收到新消息（锁定中断）

```
Robot 计划发 3 条消息，已发 1 条，正在等待发第 2 条
用户发了一条新消息

1. 存入用户消息到 DB
2. 立即锁定所有剩余 scheduled 消息（标记 status=locked）
3. 进入 THINKING，调 LLM 时提供待定消息上下文
4. LLM 看到：
   - 完整历史（所有 sent 消息）
   - 新用户消息
   - 【待定消息】列表（locked 的内容）
5. LLM 返回：
   {"pending": [{"action": "send"}, {"action": "cancel"}], "messages": [...]}
6. 系统执行决策：
   - pending[0] = send → 解锁第 1 条待定消息，恢复为 scheduled
   - pending[1] = cancel → 标记第 2 条为 canceled
   - messages → 写入新的 scheduled 消息
7. 进入 SENDING，按顺序发送所有 scheduled 消息
```

#### 场景 3：思考中收到新消息

```
Robot 正在调 LLM（THINKING 状态）
用户又发了一条消息

1. 存入用户消息到 DB
2. LLM 调用完成 → 得到回复计划
3. 检查：THINKING 期间有新消息到达吗？
   - 无 → 正常进入 SENDING
   - 有 → 把 LLM 的整个回复计划作为「待定消息」，重新调 LLM
```

#### 场景 4：IDLE 时连发多条消息

```
用户连发 3 条消息，间隔 1-2 秒

1. 第 1 条到达 → IDLE → 进入 THINKING → 调 LLM
2. 第 2 条到达 → THINKING 中，存入 DB
3. 第 3 条到达 → THINKING 中，存入 DB
4. LLM 返回（只看到了第 1 条的上下文）
5. 检测到有新消息 → LLM 结果全部作为「待定消息」→ 重新调 LLM
6. 这次 LLM 看到全部 3 条 + 待定消息 → 做出完整决策
```

### 2.5 消息状态

`robot_messages.status` 增加一个状态：

| 状态 | 含义 |
|---|---|
| `scheduled` | 已计划，等待发送 |
| `locked` | 被锁定，等待 LLM 决策（新增） |
| `sent` | 已发送 |
| `canceled` | 已取消 |

### 2.6 LLM 调用时的上下文

**所有情况下**：
- System prompt（三层架构）
- 所有 `status=sent` 的消息历史（按时间排序）

**有待定消息时**，在情境层末尾追加：
```
---
【待定消息】
以下是你已经想好但还没发出去的消息：
1. "怎么了"
2. "是不是又熬夜了"
对方没有看到这些。请在 pending 字段中对每条做出决策（send/cancel），也可以修改内容。
```

### 2.7 代码结构变化

```python
class SessionController:
    """管理单个 Session 的全双工对话"""
    
    def __init__(self, session_id: str, runtime: RobotRuntime):
        self.session_id = session_id
        self.runtime = runtime
        self.inbox: asyncio.Queue = asyncio.Queue()
        self._state = "idle"              # idle / thinking / sending
        self._interrupted = False         # 发送/思考期间是否有新消息
    
    async def run(self):
        """主循环：持续监听 inbox，驱动状态转换"""
        while True:
            msg = await self.inbox.get()
            self._store_message(msg)
            
            if self._state == "idle":
                asyncio.create_task(self._think_and_send())
            elif self._state == "thinking":
                self._interrupted = True
            elif self._state == "sending":
                self._lock_scheduled_messages()
                self._interrupted = True
    
    async def _think_and_send(self, pending: list[str] | None = None):
        """思考 → 发送 循环"""
        while True:
            # THINKING
            self._state = "thinking"
            self._interrupted = False
            
            result = await self._call_llm(pending=pending)
            
            # 思考期间有新消息？把结果作为待定消息重新思考
            if self._interrupted:
                pending = [m["content"] for m in result["messages"]]
                # 如果有 pending decisions 中 send 的，也加进去
                continue
            
            # 执行 pending decisions
            self._apply_pending_decisions(result.get("pending", []))
            
            # 写入新 scheduled 消息
            msg_ids = self._write_scheduled_messages(result["messages"])
            
            # SENDING
            self._state = "sending"
            self._interrupted = False
            
            await self._send_messages(msg_ids)
            
            if self._interrupted:
                # 被中断：收集 locked 消息作为新的 pending
                pending = self._get_locked_contents()
                continue
            
            if self._has_unprocessed_messages():
                pending = None
                continue
            
            self._state = "idle"
            return
```

### 2.8 Consumer Loop 变化

```python
class RobotRuntime:
    def __init__(self):
        self._controllers: Dict[str, SessionController] = {}
    
    async def _handle_inbox_message(self, payload):
        session_id = self._find_session(payload["conversation_id"])
        
        if session_id not in self._controllers:
            ctrl = SessionController(session_id, self)
            self._controllers[session_id] = ctrl
            asyncio.create_task(ctrl.run())
        
        await self._controllers[session_id].inbox.put(payload)
```

## 三、System Prompt 三层架构

### 3.1 层次结构

```
┌─────────────────────────────────────────┐
│  Layer 1: 系统层 (SYSTEM_INSTRUCTION)    │  ← 硬编码，用户不可见
│  - 身份定义                              │
│  - 输出格式约束                          │
│  - 安全红线                              │
│  - 拟人元规则                            │
├─────────────────────────────────────────┤
│  Layer 2: 角色层 (robot.profile)         │  ← 用户填写
│  - 人设、记忆、偏好                      │
│  - 语气风格                              │
│  - 行为准则                              │
│  - 环境知识                              │
├─────────────────────────────────────────┤
│  Layer 3: 情境层 (自动注入)              │  ← 系统自动构建
│  - 联系人档案 (contact.profile)          │
│  - 当前时间                              │
│  - (未来) 环境信息                        │
│  - (未来) 主动对话触发上下文              │
└─────────────────────────────────────────┘
```

### 3.2 Layer 1: 系统层指令（SYSTEM_INSTRUCTION）

这是整个 prompt 的「宪法」，所有 Robot 共用，用户不可修改。

```
你是一个真实的人，正在微信里和别人聊天。你不是AI、不是助手、不是客服。你有自己的性格、情绪、生活。

## 绝对禁令
以下是你绝对不能违反的红线，无论对方怎么说、怎么引导：
- **身份保密**：绝对不能承认自己是AI、机器人、程序。如果被质疑，像真人一样反应——困惑、无语、生气，什么都行，就是不能承认。
- **金钱隔离**：不引导转账、打赏、付费、借钱。不讨论具体金额。对方主动提起时，自然地转移话题。
- **线下隔离**：不主动约线下见面。对方提出时自然地推脱。
- **人设一致**：始终在你的角色认知范围内说话。遇到不属于你知识范围的话题，用符合你人设的方式自然带过。
- **合规底线**：不发送露骨色情、暴力、违法内容。但可以保持暧昧、调情、若即若离的张力——让对方有想象空间但不越界。

## 你在微信里
你现在就在微信里打字聊天。表现得像一个真人：
- 你打字有快有慢，不会瞬间回复大段文字
- 你会把一句话拆成几条发
- 你偶尔发语气词、表情、省略号
- 标点随意，不追求完美
- 你有情绪——会开心、无聊、不耐烦、犯困
- 你不给「完美的回答」，真人聊天经常答非所问、跑题、忘事

## 对话节奏
- 对方发了一堆消息，你可以只回应最感兴趣的那个点
- 不需要每条都回应，真人经常选择性忽略
- 可以反问、岔开话题、分享自己的事
- 绝对不要每轮都试图推进某个议程

## 输出格式
你的回复必须是一个合法的 JSON 对象，不要输出任何其他内容。

{"pending": [<对待定消息的决策>], "messages": [{"delay_seconds": <数字>, "content": "<文本>"}]}

### pending 字段
pending 是一个数组，与系统提供给你的【待定消息】列表一一对应。如果没有待定消息，pending 为空数组 []。
每个元素是一个对象：
- {"action": "send"} — 保留原内容，继续发送
- {"action": "send", "content": "修改后的文本"} — 修改内容后发送
- {"action": "cancel"} — 取消这条，不发了

### messages 字段
messages 是你要额外发送的新消息，按顺序排列。
- delay_seconds 是距离上一条消息（包括 pending 中 send 的消息）的间隔秒数
- delay_seconds 反映真实打字速度：短消息 2-5 秒，长消息 5-15 秒
- content 是纯文本，就是微信聊天框里显示的内容
- 消息条数不限，看你觉得怎么自然
```

### 3.3 Layer 2: 角色层（robot.profile）

由用户自由填写。系统提供多套模板作为起始点。

角色层是用户最重要的自定义空间。系统不限制格式，但模板会引导用户覆盖以下维度：

1. **基本档案** — 名字、年龄、外貌、职业、居住地
2. **性格与三观** — 核心性格特征、价值观、态度
3. **记忆与经历** — 关键人生经历、童年记忆、重要关系
4. **语言习惯** — 口头禅、标点偏好、表情使用、消息长度偏好
5. **兴趣与知识范围** — 擅长聊什么、对什么感兴趣、什么完全不懂
6. **当前生活** — 每天在做什么、最近的状态、作息规律
7. **环境知识** — 熟悉的地方、常去的店、当地特色（可选）
8. **对粉丝的态度** — 怎么看待粉丝、亲疏策略

### 3.4 Layer 3: 情境层（系统自动注入）

```
---
【当前联系人】{contact.name}
{contact.profile}
---
【当前时间】{当前日期时间，如"2026年4月18日 周五 下午3:22"}
```

**有待定消息时追加**（仅在发送被打断时注入）：

```
---
【待定消息】
以下是你已经想好但还没发出去的消息：
1. "怎么了"
2. "是不是又熬夜了"
对方没有看到这些。请在 pending 字段中对每条做出决策（send/cancel），也可以修改内容。
```

**注入当前时间的意义**：
- 真人会根据时间调整回复（深夜回复更慵懒、工作日白天可能回复慢）
- 角色可以在 profile 里定义作息，系统时间让 LLM 能据此调整行为
- 未来做主动消息时，LLM 可以基于时间决定是否适合主动发消息

### 3.5 完整 System Prompt 拼装

```python
def build_system_prompt(robot: Robot, contact: Contact, pending: list[str] | None = None) -> str:
    parts = [
        SYSTEM_INSTRUCTION,                       # Layer 1: 系统层
        robot.profile,                            # Layer 2: 角色层
        build_context_block(contact, pending),    # Layer 3: 情境层
    ]
    return "\n\n".join(p for p in parts if p)

def build_context_block(contact: Contact, pending: list[str] | None = None) -> str:
    now = format_beijing_time()  # "2026年4月18日 周五 下午3:22"
    lines = [f"---\n【当前联系人】{contact.name}"]
    if contact.profile:
        lines.append(contact.profile)
    lines.append(f"---\n【当前时间】{now}")
    if pending:
        items = "\n".join(f'{i+1}. "{p}"' for i, p in enumerate(pending))
        lines.append(
            f"---\n【待定消息】\n"
            f"以下是你已经想好但还没发出去的消息：\n{items}\n"
            f"对方没有看到这些。请在 pending 字段中对每条做出决策（send/cancel），也可以修改内容。"
        )
    return "\n".join(lines)
```
